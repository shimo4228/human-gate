# Human Gate — 人間は何を判断するか

ゲートには 2 軸ある。**いつ止まるか**は可逆性で決まる（[`coding-style.md`](coding-style.md) の
Reversibility Gate）。**止まったとき人間が何を判断するか**がこのファイル。

## artifact は機械、intent は人間

**機械化された検査で判定できる正しさ**（build / types / lint / tests / secret scan）は決定論ゲートと
review agent が持つ。**人間を artifact 検査に戻さない** — 手厚いレビュー体制は人間を降ろすための投資であり、
人間が読むためのお膳立てではない。ただしこれは**一次責任の割り当てであって保証ではない**（認可・並行性・
不可逆な副作用・未実装の要件は全 PASS のまま通る）。残余リスクは下の昇格規則で受ける。

**review agent は検査者であって承認者ではない。** LLM judge は generator–verifier gap を持つ
（提案者と検査者が同一システムなら、検査は提案者の盲点を継承する）。承認は
「決定論ゲートの PASS」＋「人間の intent 判断」で構成し、**LLM 単独の承認経路を作らない**。

## ゲートで提示するもの（対象で分岐）

- **behavior-shaping artifact**（rules / skills / identity / 憲法 / 公開ドキュメント）、
  **control plane**（hooks / `permissions` 設定 / `--allowedTools` 等の権限定義 / scheduled task 定義）、
  **および検査の証拠を作るもの**（テスト / fixture / lint 設定 / カバレッジ閾値 / CI 定義 /
  review agent の prompt / 依存）→ **本文を提示する**。1 番目はテキストが意図そのもの、
  2・3 番目は**判定そのものと判定の根拠**を動かすので、要約に畳むと「検査を緩める変更」が隠れる
  （テストを実装に合わせて書き換えれば、嘘をつかずに「全件 PASS」と要約できる）
- **実装コード・生成物** → **意図の要約**。diff 本文と機械チェックの PASS 一覧は提示しない

**昇格規則** — 不可逆・高影響な変更（データ移行 / 権限・課金 / 外部公開 / 削除処理 / 鍵ローテーション）は
**対象区分にかかわらず本文または該当差分を提示する**。第 1 軸（可逆性）は第 2 軸を上書きする。

**FAIL は例外** — 決定論ゲートが FAIL したときは**検出行そのものを提示する**（[`security.md`](security.md) の
`*_BYPASS` 偽陽性判定は人間が所有する。機械の見立てが当たっていても決定の持ち主は人間）。
ただし**秘密の実値はマスク**し、ファイル・ルール名・前後の文脈だけ出す。提示を省くのは PASS のときだけ。

**「見せない」≠「残さない」** — PASS 一覧を出さないのは人間の判断面から退避させる意味。
機械可読なログには保存し、後から展開できる状態を保つ（監査・障害調査・再現性）。

## 意図の要約は固定スキーマで出す

自由記述にしない。照合先を人間由来の referent（[`planning.md`](planning.md) 介入点 1 で承認した plan）に
固定しないと、人間は提案者自身の自己申告を検証することになる（gap が artifact 層から語りの層へ移るだけ）。
フィールドは 5 つ、すべて必須:

`承認済み意図` / `実現した変更` / `plan との差分`（**なし / あり / 再承認が必要** の 3 値）/
`ユーザー・運用への影響` / `証拠側の変更`

`plan との差分` を必須値にするのが要点 — plan からの逸脱自体は悪くないが、**逸脱が要約から消えるのが危険**。
毎回「差分なし」を読み流す運用になったら plan の粒度を上げる（ただし粒度を上げるとボトルネックが
plan 承認へ移動するので、不可逆な領域に絞る）。

この rule は **harness alignment**（AKC ADR-0017 / DOI 10.5281/zenodo.20578272）の human-gated 条項と
**line of approval**（AKC glossary）の運用版であり、定義本文は複製しない。
